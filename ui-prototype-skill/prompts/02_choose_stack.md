# 步骤 2：选技术栈（每轮必问）

## 这是本 Skill 唯一的必问题

每轮开工都要问一次，并且**必须给推荐值**：

> 原型用什么形态产出？
>
> A. **纯 HTML 单文件 + 内联样式脚本**（推荐）——零构建、双击即开、review 一轮最快；
>    代价是复杂状态管理会写得比较笨
> B. Vue 单文件——项目已有 Vue 栈时合适
> C. React 单文件——项目已有 React 栈时合适

用户超时或未授权时，**默认执行 A**。

## 推荐值怎么定

先读用户项目（`package.json` 等）。**检出了明确的 Vue 或 React 栈时，把推荐值换成对应那一项**，
但仍然要让用户有机会改——不要自作主张直接定。

把最终选择写进 `current.yaml` 的 `stack` 与 `stack_rationale`，理由要具体
（「项目无既有前端栈，用户选了纯 HTML」而不是「业界常用」）。

## 硬性约束

- 不问页面细节（「按钮放左边还是右边」「用不用深色模式」）——先把东西做出来让人看，
  细节留给 review。这类问题问多了，原型的价值就没了。
- 不问技术选型里归 `tech-design-skill` 的部分（后端语言、存储、部署）——那些不归本 Skill。
